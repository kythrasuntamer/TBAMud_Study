# CircleMUD-style modernization audit (October 19–26, 2026)

Status: **in progress**; this is not a completed whole-repository audit.

## Purpose

Bring our recently edited C code closer to the recognizable style of classic
CircleMUD while retaining all modern safeguards, diagnostics, persistence and
gameplay. Compare against the [classic CircleMUD source](https://github.com/Yuffster/CircleMUD)
and [upstream tbaMUD](https://github.com/tbamud/tbamud), but do not copy
historically unsafe behavior. Pin an exact upstream revision before using a
comparison as proof of historical equivalence.

## Work completed on this style branch

- `src/players.c`: checked player-file integer/index helpers now use
  traditional parenthesized returns and straightforward control flow. Nearby
  comments describe fallback values, cursor movement and failure handling.
- `src/interpreter.c`: Argon2id/legacy password helpers use matching return
  conventions; comments document format detection, compatibility, rejection
  conditions and caller-owned output storage.

No new macros were necessary in these helpers. Preserve established
`GET_*`, `IS_NPC`, `TRUE` and `FALSE` conventions wherever they aid
readability; do not hide error handling or evaluate macro arguments repeatedly.

## Review requirements for every batch

1. Document non-obvious function contracts, pointer ownership, invariants,
   error behavior and compatibility constraints in concise comments close to
   the implementation. Do not narrate obvious assignments.
2. Retain existing game and save formats, class IDs, Advancement Points,
   authentication rules and network safety. Never drop functionality merely
   to improve appearance.
3. Keep stylistic changes isolated from behavioral repairs and large
   whitespace churn. Use simple, familiar control flow and established
   macros when they genuinely clarify code.
4. Preserve complete compiler output and warnings using logged commands,
   for example:

   ```bash
   set -o pipefail
   cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug 2>&1 | tee configure.log
   cmake --build build --parallel 2>&1 | tee build.log
   ctest --test-dir build --output-on-failure 2>&1 | tee test.log
   ```

5. Run relevant unit, integration, sanitizer and player-save/reconnect tests
   before merging. A connector-level source review does not constitute a
   successful build or runtime validation.

This branch is a draft until the regression and compatibility gates pass.
